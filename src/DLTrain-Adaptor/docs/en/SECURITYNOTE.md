# MegatronAdaptor Security Statement

## System Security Hardening

- You can enable address space layout randomization (ASLR) at level 2 when you configure the runtime system to improve system security and enable system randomization protection.
You can configure it as follows:

  ```bash
  echo 2 > /proc/sys/kernel/randomize_va_space
  ```

## Recommended Runtime User

- For security reasons, you are advised to avoid using `root` or other administrator accounts to run any command, and to follow the principle of least privilege.

## File Permission Control

- You are advised to set the runtime system `umask` value to 0027 or higher on the host (including the host machine) and in containers. This ensures that the maximum default permissions are 750 for newly created folders and 640 for newly created files.
- You are advised to apply permission control and other security measures to sensitive files, such as the files required for training, the files saved during training, your personal privacy data, and business assets. An example is write permission control on dataset files when multiple users share a dataset. For the recommended permission settings, see Table 1.
- The permissions on the files generated when the native Megatron-LM and PyTorch frameworks run depend on the system settings, such as the dataset index files generated by Megatron-LM and the files saved by the `torch.save` interface. You are advised to apply permission control to the generated files as needed, and you can refer to Table 1 for the recommended permission settings.
- You need to apply permission control during installation and use, and you are advised to refer to Table 1 for the recommended settings. If you need to save installation or uninstallation logs, add the `--log <FILE>` argument after the installation or uninstallation command. Note that you must apply permission control to the `<FILE>` file and its directory.

### Table 1 Recommended Maximum Permission Limits for Files and Folders in Different Scenarios

| Type | Linux Permission Reference Maximum |
| -------------- | ---------------  |
| User home directory | 750 (`rwxr-x---`) |
| Program files (including script files, library files, and so on) | 550 (`r-xr-x---`) |
| Program file directory | 550 (`r-xr-x---`) |
| Configuration file | 640 (`rw-r-----`) |
| Configuration file directory | 750 (`rwxr-x---`) |
| Log files (recorded or archived) | 440 (`r--r-----`) |
| Log files (being recorded) | 640 (`rw-r-----`) |
| Log file directory | 750 (`rwxr-x---`) |
| Debug files | 640 (`rw-r-----`) |
| Debug file directory | 750 (`rwxr-x---`) |
| Temporary file directory | 750 (`rwxr-x---`) |
| Maintenance and upgrade file directory | 770 (`rwxrwx---`) |
| Service data files | 640 (`rw-r-----`) |
| Service data file directory | 750 (`rwxr-x---`) |
| Directory for key components, private keys, certificates, and ciphertext files | 700 (`rwx------`) |
| Key components, private keys, certificates, and encrypted ciphertext | 600 (`rw-------`) |
| Encryption and decryption interfaces and scripts | 500 (`r-x------`) |

## Runtime Security Statement

- You are advised to write training scripts that match the resource status of the runtime environment. If a training script does not match the resources, for example, if the memory for dataset loading exceeds the memory capacity limit or the training script generates more data locally than the available drive space, errors may occur and the process may exit unexpectedly.
- When an exception occurs during runtime, MegatronAdaptor exits the process and prints error information. You are advised to locate the specific cause of the error based on the error message, for example, by setting synchronous operator execution, checking CANN logs, or parsing the generated core dump files.
- MegatronAdaptor may load and save models while it runs. Note that its underlying implementation may use the Python `pickle` module to serialize or deserialize some files, and this module has inherent security risks.

### Special Scenarios

| Scenario | Usage | Port | Possible Risk |
|-------------------------------------| ------------------------------------------------ | ---------- | ---------- |
| You download and use an open-source dataset from Hugging Face | Call the `load_dataset` function and specify the path of the target open-source dataset | Random port | The dataset may contain sensitive or illegal content, which leads to compliance issues. The dataset may also have quality problems, such as incorrect labels or data bias, which affect data preprocessing. |
| You download corpora through `nltk.download` | You use `nltk.download` inside the code to download the corpora | Random port | If the file source is untrusted, a deserialization vulnerability may exist when the file is loaded, which can lead to file tampering. |
| You load data through `nltk.load` | You use `nltk.load` inside the code to load corpus data | Random port | The underlying implementation may call the `pickle` module, which has a deserialization vulnerability. If the data source is untrusted, a potential security risk exists. |
| You use `from_pretrained` to trust specific code and use the implementation of the related model | Call the `from_pretrained` function and set `trust_remote_code=True` | Random port | If `trust_remote_code=True`, the downloaded code may contain malicious logic or backdoors, which threatens system security. However, `local_files_only=True` is also set. Therefore, the program only runs local files to avoid this risk. |

## Vulnerability Response

We place high importance on the security of the community version. The MegatronAdaptor open-source community receives, investigates, and discloses security vulnerabilities related to this community. For details, see [Ascend Vulnerability Response](https://gitcode.com/Ascend/community/blob/master/docs/security.md).
